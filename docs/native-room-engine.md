# Native room engine

The live game uses `react-native-filament` 1.11.0 on iOS and Android. React Native retains navigation, care controls, math puzzles, wallets, localization, accessible menus, and the room editor. Filament renders every room object and cat; Bullet simulates movable toys. Store room previews and cat portraits use the same native models. Static store thumbnails, control icons, and OS launch artwork remain raster UI assets.

3D graphics is the launch default. Only an explicit Settings choice saves Simple graphics under `@mathmews/graphics-mode`. Automatic scene recovery enables it for the current session without writing a preference. The previous `@mathmews/simple-graphics` flag is ignored because it also stored automatic crash fallback and could leave the cat permanently using a still image.

See [Adding cat animations and room interactions](cat-animations.md) for clip registration, shared command menus, rebuilding and validation.

## Assets and saved rooms

`assets/3d/native/` contains the inventory models, three cat coats, and room effects. `catalog.json` records original camera scale, mesh bounds, and animation flags. `constants/native-model-sources.ts` provides Metro's static asset references. The exporter shares identical GLB buffer data without changing geometry or animations.

`scripts/3d/export-native.py` reuses the catalog generators and builds an original cat through `original_cat.py` and `game_cat.py`. The body, head, legs, ears and tail form one sealed main surface, with separate sealed ear inserts. Mesh proportions and anatomical pivots share a rest pose; smooth regional weights keep belly vertices separate from leg bending. Every coat has 36 clips: the existing 35 actions plus a separate sofa `sit` pose. Expressions and care/play props remain independently animated. Walking uses two-segment authoring IK and a distance-matched stance. Doors export closed and stationary. Foliage and appliance power/wind rules remain intact.

Regenerate with locally installed Blender:

```sh
npm run assets:native
```

The script writes editable intermediate blends under `/tmp/brainpet-native-blends`. `native_gltf.py` normalizes clip time origins and repairs unused skin slots so they reference a valid influencing bone. Filament otherwise derives invalid normal transforms from hidden zero-scale prop bones, producing black head/leg patches. GLB replacement is atomic to avoid partial asset loads. The raster pipeline now only builds catalog thumbnails. The old cat atlas renderer, play-prop pages, and isolated animation lab have been removed. `catModelRegistry` describes native clip playback, and `useAnimationActivity` shares focus, background and Reduce Motion policy across native models, videos, and UI thumbnails. Authored clip timings come directly from `scripts/3d/clips.json`.

`buildNativeRoomWorld` maps each saved normalized offset to its original screen anchor, then unprojects it into the orthographic room. It preserves item scale and wall orientation. Rugs and wall artwork retain saved front/back ordering with small depth offsets along the camera ray. No save schema or furniture placement is rewritten. An old cat spawn inside a solid object moves to the nearest available floor position.

Every placeable item supports an additional yaw of 0–360 degrees in the room editor. Toys and decorations store `rotationDegrees`; beds store `bedRotationDegrees`. These optional fields preserve existing wall flips, style variants and toy quarter turns. `utils/room-rotation.ts` normalizes angles to tenths of a degree, with a full turn equal to zero. The native model, collision bounds, seating, bathroom contact points and leaf anchors use the same heading. The rotation sheet previews locally and writes once on Apply; wall-placement repairs wait until the preview ends so Cancel cannot change saved offsets. Captured layouts, Undo, named rooms and save normalization retain the angle. Simple graphics retains fixed images and shows a hint to use 3D graphics for angle previews.

## Movement and interactions

Furniture bounds remain conservative navigation obstacles. Physical colliders also include mounted fixtures. Each sofa now exports 13 collision boxes from its individual source meshes, so its seat, back, arms, pillow and legs participate in Bullet without filling the open space above the cushions. A command computes a path around them, then smooths only collision-free segments. The cat uses a controlled kinematic body. Its walk phase advances by actual distance divided by the authored 0.8-unit stride; the default speed is 2.25 strides per second. Uniform model scale stays constant. Unreachable approaches cancel the remaining action instead of crossing a barrier. Rest and play clips hold the actual arrival position.

Sofas have seat and approach anchors derived from their exported geometry. Jumping lands on the cushion, and checks other furniture along the flight. The scheduler retains existing sit/sleep, scratching, box, ball, yarn, feather, mouse chase, care, wake-up, and door arrival behavior. Changing an action in flight waits for landing. Native playback pauses when covered or backgrounded; Reduce Motion retains completion callbacks without continuous travel.

Balls, yarn, and mice use Bullet bodies; paw proximity applies impulses, and mouse chase follows its own collision-aware route. Their transient positions drive touch targets without replacing saved resting positions. Static walls, furniture, floor, and edge rails participate in simulation. This is a rigged animation controller with rigid-body object physics and tail contact constraints. Live paw IK and active ragdoll joints are not implemented.

`native-cat-contact.ts` samples a capsule chain along the four exported tail joints and its end marker against the same furniture collision boxes, room walls and floor. After animation/cross-fading, `NativeCatActor` finds a clearing rotation about the anchored tail root, expresses it in the spine parent’s coordinate system, and updates skinning matrices. This uses Filament’s [world/local transform API](https://margelo.github.io/react-native-filament/docs/api/interfaces/TransformManager). Bone lengths and the authored curl remain intact, and the tail returns toward its authored pose when that return clears contact. Contact handling still runs with Reduce Motion. Seating faces along the centered cushions to keep the tail base clear of the backrest. This is a constrained tail pose, not a simulated chain of Bullet ragdoll joints. Other limbs retain their authored animation; the fix does not claim per-vertex collision for the whole cat.

Tail regression checks sample the actual shipped sit, curl-up and sleep skeletons across both sofa variants, mirrored layouts and supported furniture scales. They verify capsule clearance, unchanged lengths, wall-fixture contact and the actual renderer’s correction-before-skinning order. Native iOS sitting and curled sleep were visually checked; the capture is `docs/art/native-cat-rebuild/ios-tail-contact-sleep.png`.

## Native integration

`npm install` runs the pinned Filament patch in `scripts/native/patch-filament.mjs`. It adds body position, impulse, and kinematic controls to the installed C++ host bindings and TypeScript declarations. The patch is idempotent and rejects a different Filament version. Rebuild both native clients after installation or a native dependency change:

```sh
npx expo prebuild --no-clean
npx expo run:ios
npx expo run:android
```

Expo Go cannot load these modules. Babel uses the Reanimated 4 worklets plugin with nested worklet processing; the separate Worklets Core plugin must not also transform the same callbacks. Filament assets retain source data for native animator lifetime.

Native decoration touches use Filament's rendered-entity picker. Every loaded object and cat registers its renderable entity IDs; teardown removes them. A single full-room responder picks at gesture start and keeps that instance captured until release. Empty space around the arc lamp no longer intercepts the ball, and nearer visible geometry wins when objects overlap on screen. Accessibility controls and Simple graphics retain their existing targets. Coordinates reach `view.pickEntity` in local display points; the native wrapper handles density and vertical conversion. This follows the geometry-based screen picking described in [Godot's ray-casting guide](https://docs.godotengine.org/en/stable/tutorials/physics/ray-casting.html).

The drag controller retains movement while an asynchronous pick completes, coalesces updates to one per display frame and flushes the last accepted point before saving. Cancellation discards unsaved previews; stale queries cannot affect another gesture or unmounted room. Grid snapping and collision checks still run at release. Placement caches rotated box bases and uses a world-axis rejection before the separating-axis test, following the principle of reducing repeated query work described in [Unity's query optimization guide](https://docs.unity.com/en-us/engine/6000.6/manual/physics-section/physics-overview/physics-optimization/memory/raycasts-queries). Native roots reuse an identity matrix and skip transform writes when the preview has not changed. `check-room-picking.mjs` exercises delayed queries, gesture capture, frame scheduling, cleanup and rerender continuity; the stage/native checks verify instance registration, grid snapping, saved poses and 120 stationary preview frames with zero transform writes. Simulator checks confirmed lamp-shade selection, empty-space rejection and ball dragging inside the former lamp rectangle.

`node scripts/benchmark-room-placement.mjs [previous-room-item-placement.ts]` measures 2,000 drag previews and final drops against ten objects. A baseline file measures the previous per-frame collision policy; accepted preview positions intentionally differ now. On 2026-10-09, the median of seven local Node runs was 0.0027 ms per preview and 1.432 ms per drop including obstruction feedback and validity assertions. These measurements cover JavaScript placement work, not GPU timing or device frame rate.

## Verification

Room interactions use separate floor approaches and contact points. Sofa and
chair commands search front-side takeoff candidates, require a reachable floor
route and clear flights both up and down, and retain the chosen exit point.
Sitting and sleeping require arrival at the cushion in all three dimensions;
washing and toilet use require arrival at their fixture contact. Both the native
renderer and scheduler check the rendered endpoint before advancing. A blocked
step releases any held pose and ends standing instead of sleeping on the floor.
Arc-lamp collision uses separate base, shade and short stem sections so its
bounding box cannot fill the open air beneath its arch.

This follows the distinction between path following and target arrival in
[Godot's navigation guide](https://docs.godotengine.org/en/stable/tutorials/navigation/navigation_using_navigationagents.html)
and the use of furnishing interaction locations described by
[Unreal's Smart Objects](https://dev.epicgames.com/documentation/unreal-engine/smart-objects-in-unreal-engine---overview).
The existing room A* planner remains in use; no engine or navigation dependency
is required. `scripts/fixtures/sofa-navigation.json` retains an anonymized copy
of the reported layout for sofa, lamp-clearance and chair-to-sofa regressions.

Room zoom uses continuous pinch gestures on the unscaled viewport, from 1× to 3×. The point under the fingers remains anchored while zooming. The artwork and native object hit targets share the same transform; zoom no longer disables their menus. There is no zoom/reset button; pinch inward to return to 1×. Entering decoration mode automatically resets the view. `check-room-camera.mjs` covers fractional zoom, focal anchoring, pan bounds and tap/scroll thresholds. Native iOS tapping opened the sofa's Sit/Sleep menu at 2.36×, and the user confirmed one-finger panning; see `docs/art/native-cat-rebuild/ios-pinch-object-menu.png`.

Startup stills render from the shipped GLB with the portrait camera. `render-native-branding.py` writes model/portrait hashes checked by startup tests. Cat exports run this renderer and rebuild the native launch/title composites so a rebuilt cat cannot leave stale startup artwork. Native launch art requires rebuilding the iOS/Android clients.

Tail contact now refines a clearing angle instead of showing discrete 10-degree poses. An overconstrained attachment uses small local corrections instead of searching all axes on every frame. Narrow sofas seat the fixed-size cat along the cushion so the idle tail attachment clears the backrest. The 1,200-frame idle check covers five sofa sizes, requires no blocked contacts and rejects tail-tip steps above .02 units. Other poses remain authored; this is not full-body physics. Joint lookup uses the stable asset handle, UI rerenders retain the render worklet and animation clock, and unrelated hit-target updates do not rerender the room scene.

`npm run test:game` checks the entire catalog, all clips/coats, saved-placement projection, obstacle detours, unreachable targets, actual-arrival poses, cushion support, and the real cat render worklet at 30/60/120 FPS. It also covers the existing game economy, care, room editor, doors, menu dispatch, speech anchors, pause, and Reduce Motion scenarios. `npm run test:startup`, `npm run typecheck`, `npm run lint`, and `npm run assets:verify` cover launch behavior, code, and bundled asset coverage.

CI checks required asset files and gameplay behavior without size limits, size warnings, or size reports. Missing inventory models, cat coats, or core room effects still fail, while adding models does not require updating a fixed file count.

The patched iOS and Android debug clients built successfully on 2026-10-05. iOS simulator checks exercised the furnished native room, sofa landing, feeding completion, and travel to the bedroom and back. Android launched the native engine on its emulator without a startup failure; full Android interaction and real-device performance checks remain necessary.

Furniture editing uses `room-item-placement.ts` for free previews and final drop validation. While dragging, furniture follows the pointer across other objects without collision queries. After grid snapping on release, rotated per-part collision boxes determine whether the final spot is clear. Room edges use the convex silhouette of the actual exported vertices, so rotating a sparse model does not reserve the empty corners of its enclosing box. Floor limits follow the skirting inner faces (−2.3075) and the flat floor before the open-edge bevel (+2.46). An invalid drop restores the saved pose; native editing does not save the rejected placement. Arrow controls and accessibility movement validate each completed move. Old overlaps can be lifted into any clear spot, and new purchases seek nearby empty space. Rotation and resizing cannot increase overlap. Rugs remain usable beneath furniture. Movement keeps the saved yaw and wall orientation.

Lava lamps and table lamps can rest on the rectangular tables. `placeLampOnTable` intersects their screen anchor with the exported tabletop height and checks that the base fits inside the rotated, scaled surface. Drag previews lift the model and its light together; collision checks still run only at release, including other objects on the table. The same calculation reconstructs the elevated pose from saved offsets, without adding a separate height to the save. Moving off the surface restores floor height. `check-room-item-placement.mjs` covers rotated/scaled tables, base overhang, other lamps, preview/drop agreement and save/reload.

`build-placement-bounds.mjs` audits all 341 placeable GLBs and generates `constants/room-placement-bounds.json`. Static models missing custom colliders use one box per mesh part (including chair seats, legs and runners); authored sofa/plant/arc-lamp shapes and animated envelopes stay in use. The native exporter regenerates this data after item exports; run the script separately after other model changes. `check-placement-bounds.mjs` checks every mesh against the generated footprints and part bounds, and verifies the physical room edges.

Rejected drops retain the attempted footprint and structural outline in orange, with an “Attempted position” label, and outline only the obstructing collision parts or crossed room edge in red. The editing dock states that the object returned to its saved position, then names each blocker/edge in both languages and announces the reason to screen readers. Diagnostics are computed once at release or nudge, then clear on the next selection/gesture or successful placement. There are still no per-frame collision queries or React updates during furniture previews. Tests cover clear gaps beneath the rocking chair, solid seat contact, rotated edge placement, separate obstacle/boundary reasons and stage feedback/cleanup.

The selected model's live transform travels through a Worklets shared value to the Filament drawing thread. Before publishing, the editor copies the live object proxy and its bounds/position arrays: assigning a proxy back into its own Worklets Core shared value can erase its properties during a blocked drag. Native preview readers copy and validate every numeric transform before calling Filament, retaining a finite pose when an update is incomplete. The saved world and physics bodies update when movement is committed. Lamp lights, window lights, outdoor weather and AC airflow follow the same preview. `check-room-item-placement.mjs`, `check-room-decoration-motion.mjs` and `check-native-room.mjs` cover collision recovery, live-proxy self-assignment, unchanged previews, invalid drops, incomplete previews, saved angles and 120 drag frames without React updates, model reloads or body recreation. The reported 20-degree chair/sofa layout is covered by stage tests for free movement, rejected overlap, accepted clear drops and retained orientation. Simulator checks confirmed the chair moves across the sofa into a clear spot and returns to its last saved position after an overlapping drop.

Rugs are walkable support surfaces. `native-ground-support.ts` caches their scaled and rotated footprints and checks all four animated paw pivots on the drawing thread. The cat steps up before a toe pad reaches the rug edge, includes pad clearance in reclining poses, and returns to floor height after leaving. The rendered lift stays separate from navigation coordinates and arrival checks. `check-native-room.mjs` verifies the exported toe-pad vertices during walking at 30/60/120 FPS, standing, sitting, lying down and sleeping, including rotated/resized rugs and Reduce Motion.

Curtains are sold in Decor → Curtains in rose, blue and cream. Each placed pair saves `curtainOpen` (legacy pairs start open) and exposes Open/Close in both play and decoration menus. New pairs start over an existing window, using its wall orientation and aperture width; soft fabric may layer over window frames. Mounting depth uses the nearest window's frame on the same wall. Panels pivot at the hanging rod and slope over a protruding sill, so the rod stays near the frame without fabric clipping into the sill when closed. `build-window-weather.mjs` derives separate frame/sill bounds from the shipped window geometry. Bare-wall pairs keep their hardware just in front of the wall. Curtains move freely along their chosen wall, including placements whose rod or fabric extends beyond the wall edges or ceiling. Dragging, accessibility nudges, native placement and save normalization preserve the chosen anchor without full-model or square-sprite bounds. Other furniture retains its collision and room limits. The exported models retain two named panel pivots and separate fabric materials. `NativeCurtain` slides and gathers them on the drawing thread, pauses hidden rooms, applies Reduce Motion instantly and stops native writes when settled. Window-plane overlap controls backlit fabric tint and window-light transmission: closed rose/blue fabric passes 12% of covered light, cream linen 28%, with day/night and weather tint. These values are blended using the same shared opening progress as the panels. `check-curtains.mjs` covers saves, geometry, movement at 30/60/120 FPS, wall-boundary placement, lighting, pauses and idle work.

The world clock also controls the cat's routine. Night runs from 21:00 to 06:00. Four of five automatic choices favour seat naps at night and play/exploration during the day, regardless of furniture count. Automatic seat naps last two real minutes at night and 20 seconds during the day; idle activity waits are 30 and 12 seconds respectively. Empty rooms allow obstacle-aware exploration. Without a seat, an undisturbed cat rests after 30 seconds at night and sleeps after one minute, within even a 300× night. Hunger and interactions take priority. Dawn ends automatic night activities through the existing uncurl/jump-down/return sequence, deferring interruption until an airborne cat lands. Explicit sleep commands remain held. Clock-driven floor sleep stays in the display engine rather than persisting an asleep flag that could prevent waking. Clock readers poll every five seconds while active; scheduler options change only when the period changes. `check-room-activities.mjs` and `check-world-clock.mjs` cover day/night preferences, empty rooms, native clearance, dawn at all speeds, saved sleep, commands, hidden rooms and Reduce Motion.

Rain can produce distant lightning. `NativeLightning` advances one real-time storm clock on the drawing thread and shares its bounded pulse with every window light, sky/frame material and window-backed curtain in the room. Each occasional strike has a brief rise/fade and a weaker follow-up one second later; world-clock acceleration does not speed it up. Existing window lights brighten with a cold tint, including the cat and nearby objects, while closed curtains attenuate the flash. No light entities, textures or models are allocated per strike, and settled materials/lights stop updating between strikes. Hidden rooms and rooms without windows pause the storm clock; Reduce Motion suppresses flashes. The weather, clock, curtain and native scene checks cover synchronization, day/night lighting, normal-light restoration, curtain attenuation, rain ending, pauses and 30/60/120 FPS at all clock speeds.

Lava lamps use tapered transparent glass, separate round amber wax volumes and a 20-second native motion loop. Both saved lamp IDs animate only when powered on; hidden rooms and Reduce Motion retain the existing scene pause rules. One warm point light inside the bottle illuminates nearby objects and the floor. Its power scales with lamp size, while a minimum falloff radius keeps small lamps from displaying rectangular light-culling cutoffs in the orthographic simulator view. Shaded lamps also retain a minimum range and use a broad, softly faded downward spotlight. A narrower cone produced a straight horizontal cutoff in the orthographic simulator; widening it removed the edge while keeping light below the shade. The sprite fallback retains its small floor glow. Metal hardware stays non-emissive. The actual exported geometry checks cover transparency, independent wax trajectories, bottle containment and seamless loop endpoints; simulator checks confirmed the warm pool fades smoothly at night.
